# B2B / B2C Marketplace (Go + React + Docker)

An open-source, copy-and-go marketplace core. It ships the building blocks every
B2B (and B2C) marketplace needs: authentication, a multi-language product
catalog, product **analogs / cross-references**, multi-currency pricing with B2B
volume tiers, orders, an admin panel and a pluggable **payment gateway interface**.

Everything is open source.

- **Backend:** Go 1.24 · [chi](https://github.com/go-chi/chi) router ·
  [pgx](https://github.com/jackc/pgx) · PostgreSQL 16 · Nginx. A single static
  binary that runs its own SQL migrations and demo seeder on boot; no PHP,
  no Redis, no job queue. Caches (currencies, languages, settings) are
  in-process.
- **Frontend:** React 19 · Vite 6 · TypeScript · Tailwind CSS v4 — a SPA
  storefront + admin panel that consumes the API.

> The backend was originally written in Laravel and has been rewritten in Go.
> The HTTP API (routes, payload shapes, validation messages, pagination
> envelopes, bearer tokens) is kept compatible, so the React frontend runs
> unchanged and the Go service can even run against a database the Laravel
> migrations created.

## Quick start (one command)

```bash
docker compose up --build
```

That builds everything, starts PostgreSQL + the Go API + Nginx + the Vite dev
server, waits for the DB, runs migrations, and seeds demo data. Then open:

- **Storefront (React):** <http://localhost:5173>
- API base: <http://localhost:8080/api>
- Health check: <http://localhost:8080/up>

To change ports / DB credentials edit `.env` at the repo root (values are read
by `docker-compose.yml`) — or just edit the defaults inline.

## Seeded catalog

The seeder generates **~90 products across 6 categories** (electronics,
industrial, office, tools, packaging, safety), mirrored by a second supplier
(~180 products in total), each with **3 images** and organized into product
*families* whose variants are automatically linked as **analogs**. Product
images are **deterministic SVG placeholders generated by the app itself**
(`GET /img/{seed}`) — no external image host, so they always render offline.
Swap in your own image URLs anytime via the admin Product editor (one URL per
line, first = primary).

It also seeds **140 back-dated demo orders** (with payments) spread over the last
90 days, so the admin dashboard has real trends to plot on a fresh install. That
step skips itself when orders already exist and can be run on its own with
`docker compose exec app server seed:demo-orders`.

## Core concepts

- **Auth** — bearer tokens (Sanctum-compatible `{id}|{secret}` format, stored
  as SHA-256 in `personal_access_tokens`). `POST /api/auth/register` and
  `/login` return a token. B2B registration creates/attaches a `Company`.
- **Products & catalog** — categories, SKUs, brands, stock, MOQ (min order qty),
  and an `is_b2b_only` flag that hides items from B2C buyers.
- **Analogs** — interchangeable/substitute products via `product_analogs`
  (`equivalent | substitute | upgrade`), always stored symmetrically. See
  `GET /api/products/{id}/analogs`.
- **Currency** — prices stored in a base currency, converted via per-currency
  exchange rates, with optional fixed overrides and **B2B volume tiers**
  (`product_prices.min_qty`). Pass `?currency=EUR&qty=500`. Sorting and
  filtering by price use the same resolution in SQL.
- **Languages** — `?lang=ru`, the user's saved locale, or `Accept-Language`
  drives translated product/category names (`product_translations`).
- **Payments** — every provider implements `payments.Gateway`
  (`backend/internal/payments`). Built-in drivers: `fake` (sandbox) and
  `manual` (bank transfer, confirmed through `POST /api/payments/manual/callback`).
  Add Stripe/etc. by implementing the interface and registering it with
  `Manager.Extend` in `services.NewApp`.

## API tour

```bash
# Browse catalog in euros
curl 'http://localhost:8080/api/products?currency=EUR&search=cable'

# Register a B2B buyer
curl -X POST http://localhost:8080/api/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"name":"Jo","email":"jo@biz.test","password":"password","type":"b2b","company_name":"Biz LLC"}'

# Place + pay an order (use the token from login/register)
TOKEN=...
curl -X POST http://localhost:8080/api/orders -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"items":[{"product_id":1,"quantity":2}],"currency_code":"USD","shipping_address":"Main st 1"}'
curl -X POST http://localhost:8080/api/orders/1/pay -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d '{"gateway":"fake"}'
```

Validation failures return `422 {"message": "...", "errors": {"field": ["..."]}}`,
guests get `401 {"message": "Unauthenticated."}` and non-admins on `/api/admin/*`
get `403`.

## Admin panel

Sign in as the admin account and an **Admin** link appears in the header
(or go straight to <http://localhost:5173/admin>). The panel is part of the same
React SPA, guarded client-side by role and server-side by the admin middleware
on every `/api/admin/*` route.

- **Dashboard** — a 7/30/90-day window with revenue, orders, average order value
  and new-user KPIs (each against the previous window), a daily revenue/orders
  trend chart, order-status and B2B-vs-B2C breakdowns, top products and
  categories, payments per gateway, catalog health, recent orders and
  lowest-stock products. Orders placed in different currencies are converted to
  the base currency so every total is comparable.
- **Orders** — list/filter/search all orders, change status (pending → paid →
  processing → shipped → completed / cancelled)
- **Products** — full CRUD (price, stock, MOQ, category, B2B-only, active,
  images), per-product price grid (currency overrides + volume tiers) and
  analog links
- **Categories** — CRUD with parent/position/active and translated names
- **Users** — CRUD, change role (customer/manager/admin) and type (b2b/b2c),
  reset password, activate/deactivate
- **Companies** — review B2B companies and toggle verification
- **Currencies** — CRUD + exchange rates; saving flushes the price cache so the
  storefront reflects new rates immediately
- **Settings** — marketplace mode (b2c/b2b), company name/description and the
  storefront icon (uploaded files are served from `/storage/...`)

Only `admin@marketplace.test` has access by default; other accounts get `403`.

## Storefront features (React SPA)

- Catalog grid with live search, category filter, price sorting and pagination
- Product detail page with **analogs / cross-references** and live **B2B
  volume-tier** pricing as quantity changes
- Header **currency** and **language** switchers (drive API `currency`/`lang`)
- Token auth (login + B2B/B2C registration), demo accounts pre-filled
- Client-side cart → checkout → pay via selected gateway → order history

The SPA stores its token in `localStorage` and sends it as a Bearer token, so
logged-in B2B users automatically see B2B-only products and tiers.

## Project layout

```

backend/           # Go API
  cmd/server/              # entrypoint: serve | migrate | seed | seed:demo-orders
  internal/server/         # router (all routes) + integration tests
  internal/handlers/       # HTTP handlers (storefront + admin), middleware
  internal/services/       # pricing, settings, locale, orders, dashboard, accounts
  internal/payments/       # Gateway interface + fake/manual drivers

  src/api.ts       # typed API client
  src/store.tsx    # auth + cart + settings context
  src/pages/       # Catalog, ProductDetail, Login, Cart, Orders, admin/*
```

## Configuration

The API is configured through environment variables (same names the Laravel
version used, so existing deployments carry over):

| Variable | Default | Purpose |
|---|---|---|
| `APP_URL` | `http://localhost:8080` | Public URL used for generated image and storage links |
| `PORT` / `HOST` | `8000` / `0.0.0.0` | Listen address inside the container |
| `DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD` | postgres defaults | Database connection (or set `DATABASE_URL`) |
| `APP_BASE_CURRENCY` | `USD` | Fallback base currency when none is flagged in the DB |
| `APP_LOCALE` | `en` | Fallback locale |
| `MARKETPLACE_MODE` | `b2b` | `b2c` or `b2b`; overridable from the admin Settings page |
| `MARKETPLACE_COMPANY_NAME`, `MARKETPLACE_COMPANY_DESCRIPTION` | | Defaults for the storefront branding |
| `PAYMENT_GATEWAY` | `fake` | Default gateway (`fake` or `manual`) |
| `PAYMENT_MANUAL_BANK_ACCOUNT` | | Shown in manual-transfer instructions |
| `STORAGE_PATH` | `/app/storage` | Uploaded files (served from `/storage/...`) |
| `SEED_ON_BOOT` | `true` | Run the demo seeder on every start (idempotent) |
| `BCRYPT_ROUNDS` | `12` | Password hashing cost |

## Development without Docker

```bash
# PostgreSQL must be reachable; adjust DATABASE_URL as needed.
cd backend
export DATABASE_URL='postgres://b2b:secret@127.0.0.1:5432/b2b_marketplace?sslmode=disable'
go run ./cmd/server serve            # migrate + seed + listen on :8000

cd ../frontend && npm install && npm run dev   # storefront on :5173 (VITE_API_URL in frontend/.env)
```

Backend code changes take effect on restart (`go run` again); the React
frontend hot-reloads via Vite.

### Tests

```bash
cd backend
go test ./...                                   # unit tests
TEST_DATABASE_URL='postgres://b2b:secret@127.0.0.1:5432/b2b_test?sslmode=disable' \
  go test ./...                                 # + integration tests (tables are truncated!)
```

The integration suite covers the dashboard aggregation (currency conversion,
timeseries, leaderboards), settings/icon upload, the order flow (visibility,
MOQ/stock rules, tier pricing, payments, policy) and analog linking.

## Useful commands

```bash

```

## Upgrading from the Laravel version

Point the Go service at the existing database: the embedded migration is
idempotent against the Laravel schema and bearer tokens issued by Sanctum keep
working. The old `migrations`, `cache`, `sessions` and `jobs` tables are simply
left untouched. Uploaded icons previously lived in `storage/app/public`; copy
them into the `appstorage` volume (`/app/storage/public`) to keep them.
